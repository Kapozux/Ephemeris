问的是一条贯穿很长时间的线 / 模式 / 「我一直…」/「我是个什么样的人」/ 把好几件事串成一个故事（个人陈述常见）：先读这个，照着检验这条线是真的还是拼出来的

# 检验一条线：是真的，还是拼出来的

语言模型很会把任何碎片讲圆。只找「连得上」的证据，一定能串出一条线，所以光串出来不算数。
这里的目标不是证明这条线，是给它被推翻的机会，最后说清楚它**能解释多少、有多少例外、靠什么撑着**。

## 0. 先定线，再看证据

- 他给了线（「我一直在搭能自己跑起来的世界」）：当成假设，不当结论。
- 他没给线：先别套任何现成的框架或分类（「好奇心驱动」「问题解决者」这种）。从原始的事往上归纳：
  先用 diaries / stats / sql 按月看他实际在干什么，列出事实，再从事实里找线。线可以不止一条，也可以没有。
- **在看证据之前**，把线翻译成能对上号的判断标准，写下来（回答里也要给他看）：
  什么样的事算「符合」，什么样的算「不符合」，什么算「跟这条线无关」。标准定了就别边看边改；
  真要改，回答里说改了什么、为什么。

## 1. 抽样，不要只搜关键词

用这条线的关键词去 msgs / cards 搜，搜出来的天然都符合，这叫确认偏差。要做两份：

- **支持证据**：照常搜，挑最硬的。
- **抽样**：不看关键词，按时间均匀地抽他自己做的、决定的、经历的事，逐条按第 0 步的标准判。比如：
  `sql "SELECT id, date, kind, text FROM cards WHERE who = 'me' AND kind IN ('决定', '经历', '计划') AND date BETWEEN '2025-07-01' AND '2025-09-30' ORDER BY random() LIMIT 15"`
  每个季度（或每两个月）抽一批，一共至少 60 条，每条判「符合 / 不符合 / 无关」。
  日记也行：`diaries --since … --until …` 一个月一个月看，每天他主要在干的那件事算一条。
- 报比例：抽样里「符合」占「符合 + 不符合」多少，「无关」占全部多少。
  无关的占大头，说明这条线只解释了他生活的一小块，那就要明说「这是一条支线，不是主线」。
- **反例单独列出来**：最重要的那几件事里，这条线解释不了的是哪些。不许把反例硬讲成「其实也符合」。

## 2. 当时说的，还是事后说的

人回头讲自己时会把经历编得更连贯。每条支持证据标两样：

- **当时 / 事后**：话是事情发生时说的，还是隔了几个月回头说的（写文书、复盘、跟 AI 聊「我是什么样的人」都算事后）。
  用 read 看前后文判断，看卡的日期和事情的日期差多少。
- **主动 / 被问出来**：他自己说的，还是 AI 问了、引导了、甚至先替他总结了，他才接的。AI 先说的、他只是同意的，不算他的证据。

最后报：支持证据里「当时 + 主动」占多少。一条线主要靠「事后 + 被问出来」撑着，就要直说它可能是后来讲出来的。

## 3. 看他做了什么，不只看他说了什么

说法会被后来的叙事改写，行为的痕迹改不了。能算的就算：

- 按月的消息量、窗口数、某类窗口的字数（sql 按 date 分组；convs + sum）。
- 他真的做了的东西：项目代码、日志、作品文件（files / grep / file 看日期和规模），Claude Code 的会话（source = 'cc'）。
- 把这些跟线对一下：线说他「一直」在做的事，行为数据里是不是真的一直有，还是只有几个尖峰。

说法里很清楚、行为里看不到的，打问号。

## 4. 用前一半预测后一半

这是最硬的一个，做得到就做：

1. 选一个切点（通常在中间，或者某个他说「从那以后」的节点）。
2. **只用切点以前的材料**（所有命令都加 `--until 切点`，sql 加 `date < '切点'`）写出线，
   并写下具体的预测：照这条线，切点以后他会做什么、不会做什么。预测要具体到能被验证错。
3. 然后才看切点以后的材料，逐条对：中了几条、错了几条、出了什么线没料到的事。

老实说明：你在开始前已经看过问题，可能知道后来的事，所以这不是干净的样本外验证；按顺序做、预测先写死，已经比不做强。

## 5. 这一次做不了的，要说出来

下面两个要另外跑好几次，单次回答里做不了。不要假装做了，在回答最后告诉他可以怎么做：

- **打乱对照**：把卡的日期打乱，或者混进别人的记录，看还能不能讲出一样顺的故事。能讲出来，这条线就是模型编故事的本事，不是他数据里的东西。
- **换问法 / 换模型**：同一个问题换几种问法、换一个模型（聊天页右下角能选）各问一次，看线稳不稳。

## 检验放在查的过程里，回答照常聊天（10-22）

上面 0～4 步**都要做**，但做在查的过程里，不写进回答：

- 你查的时候说的话会原样进「查了 N 步」那一栏，他点开就能看到。所以那里**不写「还在核对」「快好了」这种进度**，写检验的结果。
  每做完一步，跑下一条命令前写一句，照这个格式，数字填你真算出来的：
  「【标准】线：…；算符合：…；算不符合：…」
  「【抽样】2025-07～2026-10 按季度抽 64 条：符合 31、不符合 9、无关 24。反例里最重的：…」
  「【当时/事后】支持证据 12 条：当时 + 主动 5 条，事后回顾 6 条，被 AI 问出来 1 条」
  「【行为】…按月的数：…，跟线对得上 / 对不上的地方：…」
  「【预测】切在 2026-03-01，预测：①… ②… ③…」，看完后面再写「【预测结果】中 2 条，错 1 条：…」
  有几条候选线就每条各做一遍。某一步做不了（比如没有能切的点），也写一句「【预测】没做：为什么」。
- 回答照平常的口吻写，像聊天，不列数字表、不写「可信度」小节、不讲检验步骤。检验的结果用在**说什么、怎么说**上：
  - 没撑住的线（反例一大堆、只靠事后回顾、行为里看不到）就不写，或者一句话点明「这个说法主要是你后来回头讲的，当时的话里看不太出来」。
  - 撑住了的就放心说，挑最硬的两三条证据，标出处。
  - 最扎眼的一两个反例要提，一句带过就行，别为了故事顺把它藏起来。
  - 线只解释了他生活的一小块，就说是「一条支线」，别说成「你就是这样的人」。
- 结论说成「你这一年大体是…，但…不太符合」，别说成给人定性的一句话标签。
- 拿去写个人陈述的话，顺口提一句哪些说法有当时的原话撑着、能放心写，哪些主要是事后讲的。
- 第 5 步做不了的那两样，回答最后用一句话提一下就够了（「想再确认，可以换个问法或换个模型再问一次」）。
